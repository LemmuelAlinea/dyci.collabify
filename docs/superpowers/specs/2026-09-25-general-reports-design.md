# Implementation prompt: General workplace Reports

> Hand this whole document to the implementing session. It is the full spec; every decision
> below was agreed with the owner. Follow `CLAUDE.md` (tokens, copy style, idempotent SQL,
> `npm run build` before claiming anything works) and read `handoff.md` first.

## Context

The General workplace (spaces → projects → tasks, files, repo, members) has no reports.
Owners and Managers need detailed, printable accounts of **who did what, when**, for a
project or a whole space, over any date range, with progress over time. The Education
workplace already has print-first reports (`src/pages/app/reports/`, `src/components/reports/`,
`src/lib/report.ts`) that this patch reuses and generalises. Nothing is scored as a grade.

Outcome: a **Reports** page per space with a builder rail and a live, paper-like report
document that prints to PDF, exports CSV per table, and saves as reusable templates.

## Decisions (agreed)

| Topic | Decision |
|---|---|
| Access | **Leads see everyone; members see only themselves.** A *lead* for a project = project Owner/Manager **or** space Owner/Manager of the project's space. Everyone else (project Member, space-only viewer) gets a report locked to their own work. Enforced in Postgres, not just UI. |
| Output | On-screen document + **Print / Save as PDF** (browser print, no PDF library) + **CSV per table section**. |
| Saving | **Saved templates** (config only, re-run with fresh data). Private by default, optionally shared with the space. Only author (or space Owner) edits/deletes. No snapshots. |
| Scheduling | **Out of scope.** No cron, email or notifications. |
| Sections | All four families, each toggleable: Summary + progress, Who did what, Activity timeline, Tasks/files/repo detail. |
| Space scope | **Rollup + per-project chapters**; user picks all or some projects. |
| People | Optional **people and team filter**. A member's report = this filter locked to self. |
| Dates | Presets + custom range + single day + **compare with previous period** (deltas). |
| Archived | "Include archived" toggle, **off by default**, still limited by archive visibility. |
| Layout | **Builder rail + live document** (Education reports shape). Phone: rail becomes a "Customize" sheet. |
| Navigation | Space sidebar row **Reports** (`/general/spaces/:spaceId/reports`) + a **Report** button in each project header pre-scoped to that project. |
| Data | **Report RPCs in Postgres** (`supabase/general-reports.sql`), security definer, one source of truth, SQL-tested. |
| Charts | **Hand-rolled SVG**, no chart library. |
| History gaps | **Add event logging** for task archive/restore, project status/archive changes, member join/leave/removal/level change. Only recorded from the patch date forward. |
| Letterhead | Collabify logo + space name + project name(s) + title + range + "Generated by <name>, <date>". No school name, no custom org logo. |
| Narrative | Rule-based auto sentences + optional author note. No AI. |
| Contribution score | **Optional toggle** (off by default). Adjustable weights with sliders; formula and parts printed openly under the table. |
| Presets | Weekly status, Person report, Project close-out, Space overview. |

## Part 1 — Database: `supabase/general-reports.sql` (new, idempotent)

Standard header comment like other `general-*.sql` files: what it does, run command, which
files it must run after (after `general-project-archive-rbac.sql`, i.e. last in the chain).
Every function: `security definer`, `set search_path = public`,
`revoke all … from public, anon`, `grant execute … to authenticated`. Split enum/type
additions into their own transaction if any are needed (a new enum value cannot be used in
the transaction that added it).

### 1.1 Access helpers

- `general_report_is_lead(p_project uuid) returns boolean` — `general_leads(p_project)`
  **or** caller is Owner/Manager of `space_of_project(p_project)` (`general_space_members.level`).
- `general_report_can_read(p_project uuid) returns boolean` — `can_read_general_project(p_project)`.
- Rule applied inside every report RPC, per project:
  - Not readable → project silently excluded.
  - Lead → honour `p_people` (null/empty = everyone).
  - Not lead → force people = `{auth.uid()}`; only rows whose actor/holder/author is the
    caller; project-wide **totals** (task counts, % progress) are still returned because the
    Progress tab already shows them to every reader. Never return another person's name,
    id, note or comment text to a non-lead.
- Archive visibility: archived tasks only when `p_include_archived` and
  `not general_task_hidden(task_id)`; archived projects only when `p_include_archived` and
  `can_read_general_project` (which already applies archiver + leads). Draft files
  (`general_draft_files`) are **never** reported (private to their author).

### 1.2 New history: `general_project_events`

```
id uuid pk default gen_random_uuid(),
project_id uuid not null references general_projects(id) on delete cascade,
task_id uuid null references general_tasks(id) on delete cascade,
actor_id uuid null references profiles(id) on delete set null,
subject_id uuid null references profiles(id) on delete set null,  -- person affected
kind text not null check (kind in ('task_archived','task_restored','project_status',
  'project_archived','project_restored','member_joined','member_left','member_removed',
  'member_level')),
detail jsonb not null default '{}',   -- e.g. {from,to} for status/level
created_at timestamptz not null default now()
```
- Indexes: `(project_id, created_at)`, `(actor_id, created_at)`.
- Append-only: RLS on, **no** insert/update/delete policies; select policy =
  `general_report_can_read(project_id)` and (`general_report_is_lead(project_id)` or
  `actor_id = auth.uid()` or `subject_id = auth.uid()`) and task not hidden.
- Written by `after` triggers (security definer, `auth.uid()` as actor, null when service):
  - `general_tasks` update of `archived_at` null↔not null → `task_archived`/`task_restored`.
  - `general_projects` update of `status` → `project_status {from,to}`; `archived_at` → archived/restored.
  - `general_members` insert → `member_joined`; delete → `member_left` when actor = subject,
    else `member_removed`; update of `level` → `member_level {from,to}`.
- Triggers must not fire extra rows during cascades from a project delete (check
  `pg_trigger_depth()` / parent existence like `guard_general_archived_task_child`).
- Record the go-live timestamp: `general_report_history_since()` returns the earliest
  `created_at` in this table (or the file's install time stored in a one-row settings table);
  the UI prints "Not recorded before <date>" for these kinds when the range starts earlier.

### 1.3 Templates: `general_report_templates`

```
id uuid pk, space_id uuid not null references general_spaces(id) on delete cascade,
owner_id uuid not null references profiles(id) on delete cascade,
name text not null check (char_length(btrim(name)) between 1 and 80),
description text not null default '' check (char_length(description) <= 280),
shared boolean not null default false,
config jsonb not null,           -- ReportConfig v1 (see Part 2), validated client-side
created_at, updated_at timestamptz not null default now()
```
- RLS: select = owner, or (`shared` and `is_general_space_member(space_id)`);
  insert = `owner_id = auth.uid()` and space member and space not archived;
  update/delete = owner or `general_space_has(space_id, 'manage')` (space Owner).
- `updated_at` trigger. Limit 50 templates per owner per space (trigger raises
  "You have 50 saved reports in this space. Delete one to save another.").

### 1.4 Report RPCs

Common parameters (same names everywhere):
`p_space uuid, p_projects uuid[] /* null = all readable in space */, p_from timestamptz,
p_to timestamptz /* exclusive */, p_people uuid[], p_teams uuid[], p_include_archived boolean`.
Teams resolve to their members (`general_team_members`, and space teams via
`general_space_team_members`) and union with `p_people`. The client converts the chosen
local dates to `[from 00:00, to+1 00:00)` in the viewer's time zone and passes `p_tz text`
where day bucketing is needed.

1. `general_report_scope(p_space, p_projects)` → `project_id, name, status, archived,
   is_lead, points_enabled, starts_on, ends_on, member_count`. Used first; tells the UI which
   projects are full vs self-only.
2. `general_report_summary(common)` → one row per project: `tasks_total, todo, in_progress,
   done, done_in_range, created_in_range, overdue_now, due_in_range, points_total,
   points_done, minutes_in_range, comments_in_range, files_in_range, commits_in_range,
   reviews_opened, reviews_applied, reviews_declined, members_active` (distinct actors in range).
3. `general_report_progress_series(common, p_tz text)` → `project_id, day date, done_count,
   total_count, done_points, total_points` for every day in range. Reconstruct from
   `general_task_events` (`created`; `updated` with `status_from`/`status`, `weight_from/to`)
   plus archive events; tasks with no events fall back to `created_at`/`completed_at`.
4. `general_report_people(common)` → one row per person per project: `user_id, name,
   level, teams[], tasks_held_now, tasks_finished_in_range, tasks_finished_late,
   points_finished, minutes_logged, comments, files_uploaded, commits, files_changed
   (from general_blobs), reviews_requested, reviews_done (decided_by), reviews_applied_as_author,
   first_activity, last_activity`. "Late" = `completed_at > due_at`.
5. `general_report_activity(common, p_kinds text[], p_before timestamptz, p_limit int
   default 200)` → unified feed, newest first, keyset-paginated by `(at, id)`:
   `at, id, project_id, actor_id, actor_name, subject_id, subject_name, kind, task_id,
   task_title, detail jsonb`. Union of: task events (created/updated/assigned/unassigned),
   comments (kind `comment`, **no body** — body length only), time logs (`time_logged`
   minutes + note for self or lead), task files (`file_added`/`file_archived`), commits
   (`commit` seq, message, file counts), repo changes (`review_requested`,
   `review_applied`/`declined`/`withdrawn`), repo comments (`review_comment`),
   project events (Part 1.2).
6. `general_report_tasks(common)` → `task_id, project_id, title, status, team, holders
   (names), created_by, created_at, starts_at, due_at, completed_at, late boolean,
   weight/points, minutes_in_range, minutes_total, comments, files, archived`.
   Cap 2,000 rows; return `truncated boolean`.
7. `general_report_time_logs(common)` → `logged_on, user, task, minutes, note`.
8. `general_report_commits(common)` → `seq, at, author, message, added, changed, removed,
   change_title, reviewer`.
9. `general_report_reviews(common)` → `title, author, reviewer, status, opened_at,
   decided_at, decided_by, files, comments, hours_open`.

Performance: add indexes if missing on `general_task_logs(project_id, logged_on)`,
`general_task_comments(project_id, created_at)`, `general_commits(repo_id, created_at)`,
`general_repo_changes(project_id, created_at)`, `general_task_events(project_id, created_at)`.
Every RPC must finish < 300 ms on a 5k-task project (check with `explain analyze`).

### 1.5 Registration
- Append `general-reports` to `ORDER` in `scripts/schema-drift.mjs`.
- Append the file to the restore command in `docs/07-backup.md`.
- Tests: `supabase/tests/general-reports.test.sql` (NOTICE PASS/FAIL, rolls back), covering:

  space-only viewer gets totals and no names; space Owner is a lead in every project;

  each new trigger writes the right event and nothing during a project delete cascade;
  template RLS (private invisible to others, shared visible, only author/space Owner edits,
  50 cap); every RPC revoked from anon.

## Part 2 — Client libraries (pure, unit-tested with Vitest)

- `src/lib/general/reportConfig.ts`
  ```ts
  type ReportSectionId = 'summary' | 'narrative' | 'progress' | 'status' | 'forecast'
    | 'people' | 'score' | 'activity' | 'tasks' | 'timeLogs' | 'commits' | 'reviews'
    | 'projectComparison'
  interface ReportConfig {
    version: 1
    scope: 'project' | 'space'
    projectIds: string[] | 'all'
    range: { preset: RangePreset; from?: string; to?: string }  // YYYY-MM-DD local
    compare: boolean
    people: string[]; teams: string[]
    includeArchived: boolean
    sections: Record<ReportSectionId, boolean>
    activityKinds: string[]            // empty = all
    groupActivityBy: 'day' | 'person' | 'project'
    score: { weights: { points: number; hours: number; repo: number; comments: number } }
    title?: string; note?: string
  }
  ```
  `defaultConfig(scope)`, `PRESETS` (the 4 below), `parseConfig(unknown): ReportConfig`
  (hand-written validator — no zod in deps; unknown keys dropped, bad values → defaults),
  `toSearchParams` / `fromSearchParams` (URL is the source of truth; short keys; shareable).
- `src/lib/general/reportRange.ts` — `RangePreset = 'today' | 'yesterday' | 'thisWeek'
  (Mon start) | 'last7' | 'last30' | 'thisMonth' | 'lastMonth' | 'projectDuration' | 'all'
  | 'custom' | 'day'`; `resolveRange(preset, now, project?) → {from, to}` (local dates);
  `previousPeriod(range)` (same length, immediately before); `toUtcBounds(range, tz)`.
- `src/lib/general/reportScore.ts` — per person, each part = person's share of the in-range
  total for that part (0–1); score = Σ weight × share, normalised so weights sum to 100;
  returns parts for display. Weights default points 50, hours 20, repo (commits+reviews) 20,
  comments 10. Ties keep name order. Zero-total parts are skipped and weights re-normalised.
- `src/lib/general/reportNarrative.ts` — deterministic sentences, sentence case, no
  exclamation marks, no "successfully": progress ("12 of 20 tasks are done (60%), 4 more
  than the previous period."), overdue, most finished (lead only), hours, reviews waiting,
  forecast state from `projectForecast`. Member reports use "You" phrasing.
- `src/lib/api/generalReports.ts` — typed wrappers for every RPC + template CRUD.
- Reuse: `src/lib/report.ts` (`toCsv`, `downloadCsv`, `reportFilename`, `generatedOn`,
  `pct`), `src/lib/general/progress.ts`, `forecast.ts`, `history.ts describeEvent`
  (extend for the new kinds), `dates.ts`.
- Tests: `reportConfig.test.ts` (round-trip URL, bad input), `reportRange.test.ts`
  (every preset, month edges, DST-free Manila + one DST zone), `reportScore.test.ts`,
  `reportNarrative.test.ts`.

## Part 4 — Layout and components (`src/components/general/reports/`)

### 4.1 Page shape
- Desktop ≥ 1024px: two columns. **Left rail** 320px, sticky, scrolls independently.
  **Right**: sunken backdrop with the document centred at A4 width (210mm ≈ 794px max),
  paper surface, 48px padding, soft shadow — same as Education `Reports.tsx` (@container split).
- Tablet 768–1023: rail collapses to a top bar with scope/range chips + "Customize" button
  opening the rail in a side `Modal`.
- Phone < 768: document full width (16px gutters), sticky bottom bar: Customize · Print · More.
  Tables scroll horizontally inside their card, never the page.

### 4.2 Builder rail (`ReportBuilder.tsx`) — top to bottom
1. **Start from**: 4 preset cards + "Saved reports" list (mine / shared, with ActionMenu:
   Open, Rename, Share/Unshare, Duplicate, Delete with ConfirmDialog).
2. **Scope**: Project | Space segmented control; project multi-select (checkbox list with
   search, "All projects"); self-only projects labelled "Your work only".
3. **Dates**: preset `Select`, custom from–to (`Input type="date"`), single day,
   "Compare with previous period" `Toggle`.
4. **People** (leads only; members see a locked "You" chip + explanation): people checklist
   with search, team checklist.
5. **Sections**: grouped checkboxes (Summary: KPIs, narrative, progress over time, status,
   forecast · People: per-person table, contribution score · Activity: timeline + kind
   filter chips + group by · Detail: tasks, time logs, commits, reviews · Space: project
   comparison).
6. **Score weights** (only when score on): four sliders summing to 100, live preview.
7. **Options**: Include archived toggle; report title; author note (Textarea, 2,000 chars).
8. **Actions**: Save / Save as (name, description, share toggle), Print, CSV (ActionMenu:
   one item per table section), Copy link.
Use existing primitives: `Select`, `Field`, `Input`, `Toggle`, `Tabs`, `Modal`,
`ConfirmDialog`, `ActionMenu`, `FilterSearch`, `Badge`, `Button`. Add a small shared
`CheckboxList` in `src/components/ui/` (there is none; raw checkboxes exist in
`MembersTab.tsx:237`).

### 4.3 Report document (`ReportDocument.tsx`)
Generalise `src/components/reports/Sheet.tsx`: add props `letterhead` and `footerNote`
(defaults keep Education output byte-identical). General letterhead: Collabify logo ·
space name · project name(s) · report title · range ("1–30 Sep 2026", plus "compared with
1–31 Aug 2026") · "Generated by <name> on <date, time>" · scope note for members ("This
report shows your own work. Owners and Managers see everyone.").
Order of blocks (each only if enabled):
1. **Table of contents** (space scope or > 3 sections), anchor links, hidden in print if 1 page.
2. **Summary**: `Figures` KPI row — Tasks done (x of y), Progress %, Finished in range,
   Overdue, Hours logged, Commits, Reviews applied — each with ▲/▼ delta when compare is on.
3. **Narrative** sentences + author note (quoted block, author name).
4. **Progress over time**: SVG line/area of % done per day (points if enabled), dashed line
   for previous period, today marker, project end date marker.
5. **Status**: donut (To do / In progress / Done / Overdue) + legend with counts.
6. **Forecast**: reuse `projectForecast` wording.
7. **Project comparison** (space scope): table per project — progress bar, done/total,
   overdue, hours, active people, commits, last activity; sortable.
8. **Who did what**: sortable table (columns from `general_report_people`), per-person
   horizontal stacked bar (finished / in progress / late), optional **score** column with
   parts; formula printed below ("Score = 50% points share + 20% hours share + …, shares of
   this report's totals. It is not a grade.").
9. **Activity timeline**: grouped by day (default) / person / project; each row
   `time · avatar initial · "Ana Cruz moved Chapter 2 to Done" · project chip`; sentences
   from `describeEvent` extended to all kinds; "Load more" on screen, print renders up to
   the loaded rows with a line "Showing the latest N of M events".
10. **Tasks**, **Time logs**, **Commits**, **Reviews**: `ReportTable` with right-aligned
    numbers, late rows marked with text (not colour alone), archived rows tagged.
11. Space scope: after the rollup, **one chapter per project** (`break-before: page` in print)
    repeating enabled sections 2–10 for that project.
Footer: "Collabify · <space> · page break-safe" note, generation stamp.

### 4.4 Charts (`reports/charts/`)

### 4.7 States and copy

range; new-event kinds before go-live: "Archiving and membership changes are recorded

exclamation marks, no "successfully".

### 4.8 Presets
| Preset | Range | Scope | Sections |
|---|---|---|---|
| Weekly status | last7, compare on | current project (or space) | summary, narrative, progress, status, activity, tasks (overdue first) |
